- `V06_SPEC.md` is absent from the repository. Use the six explicit requirements in Prompt 01 as the supplied specification for section 2.1; do not fabricate other sections or change the release scope.
- Create `release/0.6.0` from committed `feature/skills-overhaul` (`752c442`). Preserve the existing unfinished HUD/localization, ally art and menu files; include only this prompt's changes in its commit.
- No art or audio generation is needed. Use existing card/slot artwork and existing UI sounds through their current fallback system.
- Before production edits, the three-test reproduction had 1 pass (old active/passive swaps work) and 2 failures: a full loadout's missed random roll has no replacement action, and cancelling a milestone swap resumes/advances instead of restoring its cards. Remove that old path; the new flow restores the same pending pick at every Back step.
- The prompt's replacement eligibility is any full active/passive kind with an unowned same-kind skill, including on milestones. Ordinary milestone cards retain their original kind restriction. Innates and companions cannot be replaced.
- Back returns to the original reward cards from all three steps. Cache one candidate draw per kind for that pending pick so reopening cannot reroll it for free. Confirmation spends exactly that pick; it preserves the slot's position, resets level/cooldown/state and keeps removed skills in their owner pool.
- A fully maxed boss draft may have no upgrade cards. If replacement is possible, show its deterministic action rather than skip the reward; if no legal card or replacement exists, continue the queue as before. Sample up to 3 distinct candidates when fewer than 3 unowned skills remain.
- Existing effects already cast by a removed active finish normally. Replacement changes the equipped skill, ready cooldown, event subscriptions, passive counters/modifiers and HUD immediately; it does not undo earlier damage/healing or cancel unrelated effects.
- The read-only Skills dialog keeps Back visible and scrolls its own card list when needed; the pause menu only gains its requested entry. No broader pause-menu styling or release-version bump is part of Prompt 01.
- Full-check limitation: the pre-existing, untracked `tests/i18n-overhaul.test.js` reports French `MANA` and `Cacao` as untranslated because they equal their English spelling. This was the sole failure before this prompt and remains the sole failure (307/308). Do not modify that earlier localization work or its test as part of replacing skills; run the build separately because `npm run check` stops after the test failure.
- Verification uses the preserved working tree, including the earlier unfinished translations. Only Prompt 01 hunks are committed; those older files/assets stay uncommitted. Screenshot checks additionally reject overlapping footers and content escaping card borders, and verify that the Skills list can scroll to show both innate traits.

## Prompt 04 — Fullscreen viewport and safe areas — 2026-10-04

- `V06_SPEC.md` is still absent. The five explicit Prompt 04 requirements are the available section 2.4 specification. Keep `release/0.6.0`, preserve earlier uncommitted localization/artwork, and commit only this prompt's changes. No new images, dependencies, audio-file edits, package-version bump or APK signing.
- Letterboxing comes from a fixed 1280×720 Phaser FIT viewport combined with forced 100% canvas CSS and `object-fit: contain`. The Android window also lacked explicit cutout/edge-to-edge handling and only applied immersive flags at creation. Use RESIZE without fixed dimensions or centering margins; retain the existing pixel-art renderer.
- The full canvas always renders behind cutouts; only interactive UI is inset. Expose `--safe-*` as the maximum of CSS `env(safe-area-inset-*)` and the native fallback, not their sum. Consume native window insets so the WebView is not also padded; convert physical inset pixels to CSS pixels using devicePixelRatio.
- A uniform camera zoom of canvasHeight / 720 is used throughout 4:3–21:9 and all seven requested resolutions. At wider than 2.4:1, uniform scaling, a capped world width, fixed 720-unit height and no bars cannot all coexist. Conservatively cap world width at 1728, preserve the vertical zoom, and increase only horizontal zoom beyond that limit. This fallback is tested at 4000×1000; it never applies to the requested sizes. No cropping or bars are introduced.
- Derive camera bounds immediately from its current size/zoom/scroll instead of waiting for Phaser's cached worldView pre-render update. Preserve the previous viewed center even if CameraManager has already resized its camera. Keep resizing active while a reward/pause choice freezes gameplay; unregister the resize listener on cleanup.
- Pickup attraction and skill radii/ranges remain world-unit mechanics, not pixel dimensions: keep the existing 170-unit pickup range and innate multiplier. Normal enemy/boss spawns use fresh viewport bounds; explicitly requested spawn radii remain reserved for existing boss-summoned adds and QA, which intentionally spawn near the hero. Do not redesign those attacks.
- Ground/fog/full-screen shading cover current world bounds with overscan. Terrain chunks and distance-culling limits cover the live camera plus a world-unit buffer rather than a fixed screen. Normalize shake on both axes including Phaser's zoom/matrix multiplication; refresh manual pointer world coordinates against the current camera before aiming.
- The safe-area overlap regression exposed XP/manual-attack overlaps at 568×320 and 960×540 and an ally/boss-bar overlap at 4:3. Clamp existing XP/indicator/boss anchors into the available space, retaining all six action plates, 44 px targets, and identical physical EN/AR placement. Do not restyle the HUD.
- Android keeps minSdk 26 / targetSdk 36 and its existing orientation policy. Use guarded modern immersive APIs from API 30, legacy sticky flags on older devices, ALWAYS cutout mode from API 30 and SHORT_EDGES on API 28–29; reapply after focus/resume/configuration changes. An initial lint failure exposed an API 27 theme item at minSdk 26; remove that unnecessary item, not the compatibility floor.
- Debug and release Java compilation, resource processing and lint are checked offline; no assemble/sign tasks are run because keystores are excluded. No adb device or running emulator is connected, so physical cutout/system-bar behavior is explicitly unverified. Manual checks are in `VIEWPORT.md`.
